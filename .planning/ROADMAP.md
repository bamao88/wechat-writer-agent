# 路线图: 微信公众号文章撰写 Agent

## 概述

本路线图旨在修复 Agent SDK 的工具调用机制,使 Agent 能够在生成文章时自动调用 NotebookLM 知识库检索工具。通过 3 个阶段,每个阶段都在 MiniMax API 上验证效果,从工具注册与协议兼容性、工具调用验证与会话历史处理,到错误处理与 API 差异文档化,确保系统能够实现真正的"知识驱动写作"。

## 阶段

**阶段编号:**
- 整数阶段 (1, 2, 3): 计划的里程碑工作
- 小数阶段 (2.1, 2.2): 紧急插入工作 (标记为 INSERTED)

小数阶段按数字顺序出现在其周围的整数阶段之间。

- [ ] **阶段 1: 工具注册与协议验证** - 配置 SDK 并验证 MiniMax API 的工具调用协议兼容性
- [ ] **阶段 2: 工具调用验证与会话历史处理** - 验证 Agent 自动调用工具并确认会话历史格式正确
- [ ] **阶段 3: 错误处理与 API 差异文档化** - 实现完整错误处理并记录 MiniMax API 特性

## 阶段详情

### 阶段 1: 工具注册与协议验证
**目标**: SDK 能够成功发现并注册 NotebookLM 工具,且 MiniMax API 正确解析工具定义

**依赖**: 无 (首个阶段)

**需求**: TOOL-01, TOOL-02, TOOL-03, TOOL-04, API-01, API-02

**成功标准** (必须为真):
  1. SDK 启动时能从文件系统加载 NotebookLM Skill
  2. 工具注册日志显示 NotebookLM 工具已成功注册
  3. `requirements.txt` 包含 `claude-agent-sdk>=0.8.0` 依赖
  4. MiniMax API 正确解析 tool_use 块并返回 tool_result 格式
  5. 工具定义(tool schema)在 MiniMax API 的响应中格式正确且可识别

**计划**: 待定

计划:
- [ ] 01-01: 待规划

### 阶段 2: 工具调用验证与会话历史处理
**目标**: Agent 在生成过程中能自动调用 NotebookLM 工具,且 MiniMax API 正确处理包含工具调用的会话历史

**依赖**: 阶段 1

**需求**: VAL-01, VAL-02, VAL-03, VAL-04, API-03

**成功标准** (必须为真):
  1. Agent 在缺少素材时自动调用 NotebookLM 工具(无需人工干预)
  2. 日志系统记录的 `tool_call_count` 大于 0(不再永远为 0)
  3. 工具调用日志包含工具名称、调用时机、查询参数、返回结果摘要
  4. 集成测试能复现工具调用并验证返回的知识内容被用于生成
  5. 多轮会话测试验证 MiniMax API 正确处理包含 thinking/text/tool_use 的会话历史

**计划**: 待定

计划:
- [ ] 02-01: 待规划

### 阶段 3: 错误处理与 API 差异文档化
**目标**: 系统能够识别和处理工具调用失败场景,并文档化 MiniMax API 与官方 Anthropic API 的差异

**依赖**: 阶段 2

**需求**: ERR-01, ERR-02, ERR-03, ERR-04, API-04

**成功标准** (必须为真):
  1. NotebookLM 子进程调用失败时,错误日志显示明确的失败原因(退出码、stderr 输出)
  2. NotebookLM 查询超过 10 秒时,系统能检测超时并终止子进程
  3. 工具调用失败时,Agent 能回退到基于提示词的生成模式(不抛出异常)
  4. 日志系统记录工具调用的完整生命周期(注册、调用请求、工具执行、响应返回、错误捕获)
  5. 文档记录 MiniMax API 不支持的参数(如 `mcp_servers`, `context_management`)及建议的替代方案

**计划**: 待定

计划:
- [ ] 03-01: 待规划
