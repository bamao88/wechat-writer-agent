# MiniMax API vs Official Anthropic API Differences

本文档记录 MiniMax API (Anthropic 兼容接口) 与官方 Anthropic API 的差异，帮助开发者理解兼容性约束并提供解决方案。

## 概述

MiniMax 提供与 Anthropic 兼容的 API 接口 (`https://api.minimaxi.com/v1`)，支持使用 Anthropic SDK 调用 MiniMax 模型。但存在以下关键差异...

## 不支持的参数

| 参数 | 官方 API 支持 | MiniMax 支持 | 替代方案 |
|------|---------------|--------------|----------|
| `mcp_servers` | ✅ | ❌ | 使用 Skill 系统 (`setting_sources=['user']`) |
| `context_management` | ✅ | ❌ | 手动管理会话历史 |
| `computer_use` | ✅ | ❌ | 不支持，无替代 |
| `betas` | ✅ | ❌ | 不支持 beta 功能 |

## 已验证的兼容功能

| 功能 | 状态 | 验证日期 | 备注 |
|------|------|---------|------|
| Tool Use (tool_use/tool_result) | ✅ 兼容 | 2026-01-28 | 阶段 1-2 验证通过 |
| Skill 工具发现 | ✅ 兼容 | 2026-01-28 | 使用 setting_sources=['user'] |
| 流式响应 (SSE) | ✅ 兼容 | 2026-01-28 | 需要 3000s 超时配置 |
| 会话历史 | ✅ 兼容 | 2026-01-28 | Messages API 格式 |
| Thinking 功能 | ✅ 兼容 | 2026-01-28 | MiniMax-M2.1 支持 |

## 配置差异

### 环境变量

MiniMax API 需要以下配置：
- `ANTHROPIC_BASE_URL`: `https://api.minimaxi.com/v1` (必须)
- `ANTHROPIC_API_KEY`: MiniMax API 密钥 (注意：名称仍使用 ANTHROPIC 前缀)
- `API_TIMEOUT_MS`: `3000000` (推荐，3000秒超时)

### 认证头

MiniMax 使用 `Authorization: Bearer {api_key}` 格式，与 Anthropic 的 `x-api-key` 头不同...

## 已知问题与解决方案

### 问题 1: 推理任务超时
**症状**: 复杂任务在 30 秒后中断
**原因**: SDK 默认超时太短
**解决方案**: 设置 `API_TIMEOUT_MS=3000000` (3000秒)

### 问题 2: Hooks 阻塞 SSE 流
**症状**: 流式响应卡住，最终超时
**原因**: 同步操作阻塞 async 事件循环
**解决方案**: 所有 hooks 使用 async def，避免阻塞 IO

### 问题 3: 工具注册失败
**症状**: NotebookLM 工具未出现在可用工具列表
**原因**: 使用了 `tools` 参数而非 `allowed_tools`
**解决方案**: 使用 `allowed_tools=['Skill']` 和 `setting_sources=['user']`

## 最佳实践

1. **超时配置**: 始终设置 `API_TIMEOUT_MS=3000000`
2. **Hooks 实现**: 使用 async 函数，避免阻塞
3. **工具注册**: 使用 Skill 系统，不要手动定义工具
4. **错误处理**: 实现优雅降级（参见 ERR-03）

## 版本兼容性

| MiniMax 模型 | claude-agent-sdk 版本 | 验证状态 |
|-------------|----------------------|---------|
| MiniMax-M2.1 | >=0.1.23 | ✅ 验证通过 |

- Claude Agent SDK: https://github.com/anthropics/claude-agent-sdk
