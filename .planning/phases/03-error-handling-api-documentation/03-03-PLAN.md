# Anthropic API 差异文档

## 概述

本项目同时支持官方 Anthropic API 和 MiniMax API 兼容层。
本文档记录两者之间的关键差异,帮助开发者理解配置选择。

## 推荐配置

**官方 Anthropic API (推荐)**
- 无需设置 ANTHROPIC_BASE_URL
- 标准认证方式
- 完整的 SDK 功能支持

## API 差异对照表

| 特性 | 官方 Anthropic API | MiniMax API |
|------|-------------------|-------------|
| 基础 URL | api.anthropic.com (默认) | api.minimaxi.com |
| 认证方式 | 标准 API Key | 自定义 Authorization Header |
| 超时建议 | 120 秒 | 3000 秒 (推理模型) |
| Temperature | 支持 0.0 | 最小 0.001 |
| mcp_servers | 支持 | 不支持 |
| context_management | 支持 | 不支持 |
| 工具调用协议 | JSON | XML (内部转换) |

## 不支持的参数

### MiniMax API 不支持的参数

1. **mcp_servers**
   - 官方 API: 支持通过 MCP 协议连接外部服务
   - MiniMax: 不支持
   - 替代方案: 使用 Skills 或直接子进程调用

2. **context_management**
   - 官方 API: 自动管理上下文窗口
   - MiniMax: 不支持
   - 替代方案: 手动管理 max_tokens 和消息历史

3. **streaming_options**
   - 官方 API: 支持 think 流式输出配置
   - MiniMax: 有限支持
   - 替代方案: 使用默认流式配置

## 代码中的条件处理

本项目通过 `ANTHROPIC_BASE_URL` 自动检测 API 类型:
- 包含 "minimaxi.com" → MiniMax 模式
- 其他情况 → 官方 API 模式

检测代码位置: `src/modules/agent_sdk.py`
温度验证: `src/utils/temperature.py`

# 故障排除指南

## 快速诊断

运行诊断脚本快速定位问题:
```bash
python scripts/diagnose_sdk_tool_calling.py --verbose
```

诊断脚本会检查四个阶段:
1. 技能发现 - 验证 NotebookLM 技能目录和配置
2. 环境变量 - 检查必需的环境变量
3. 独立技能调用 - 直接测试技能脚本
4. Agent SDK 配置 - 验证 SDK 设置

## 常见问题

### 1. "Command failed with exit code 1"

**症状**: Agent SDK 调用工具时返回退出码 1

**可能原因**:
- NotebookLM skill 未正确安装
- 环境变量未传递给子进程
- skill 脚本内部错误

**诊断步骤**:
1. 运行诊断脚本: `python scripts/diagnose_sdk_tool_calling.py --verbose`
2. 检查 NOTEBOOK_ID 环境变量是否设置
3. 手动执行技能脚本验证

**解决方案**:
- 确保 `~/.claude/skills/notebooklm/` 目录存在
- 确保 `.env` 文件包含 NOTEBOOK_ID

### 2. "NotebookLM 未认证"

**症状**: 查询返回认证错误

**解决方案**:
```bash
python ~/.claude/skills/notebooklm/scripts/run.py auth_manager.py setup
```

### 3. "tool_call_count 始终为 0"

**症状**: Agent 不调用工具

**可能原因**:
- allowed_tools 未包含 "Skill"
- setting_sources 未包含 "user"
- 提示词未触发工具调用

**解决方案**:
- 确保 SDK 配置正确 (检查 agent_sdk.py)
- 使用空 search_results 强制工具调用

### 4. "查询超时"

**症状**: 工具调用超过 3 分钟

**可能原因**:
- NotebookLM 浏览器自动化缓慢
- 网络问题

**解决方案**:
- 检查网络连接
- 考虑增加超时时间
- 检查 NotebookLM 服务状态

### 5. API 认证失败 (401)

**症状**: HTTP 401 Invalid API key

**解决方案**:
- 官方 API: 检查 ANTHROPIC_API_KEY
- MiniMax: 检查 API 密钥格式和有效性

[TOOL-LIFECYCLE] NotebookLM | Phase: response         # 结果返回
[TOOL-LIFECYCLE] NotebookLM | Phase: error            # (如果失败)
```
