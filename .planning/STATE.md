### 决策

决策记录在 PROJECT.md 的关键决策表中。
影响当前工作的最近决策:

- 使用 SDK 模式(而非传统模式) — 需要完整的工具调用日志和指标收集
- 预检索 + 按需检索双阶段 — 既提供初始素材,又允许 Agent 智能追查
- 四阶段管道架构 — 清晰分离关注点,易于调试和扩展

**新增决策(来自 01-01):**
- 使用 setting_sources=['user'] 从 ~/.claude/skills/ 加载 Skills
- 在 allowed_tools 中使用 'Skill' 类别启用所有已发现的 Skills
- 将 _get_tools_config 重命名为 _get_allowed_tools 以对齐 SDK 参数名称

**新增决策(来自 01-02):**
- 使用 30 秒显式超时防止 API 调用无限挂起
- 创建 SDK 旁路诊断脚本隔离 API vs SDK 问题
- 双层超时保护: asyncio.timeout(30) + pytest.mark.timeout(60)

**新增决策(来自 02-01):**
- 设置 API_TIMEOUT_MS=3000000 (3000秒) 支持 MiniMax M2.1 推理任务
- 在 hooks 模块文档中明确 async 安全要求,防止阻塞 SSE 流
- 添加 CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 减少高速流解析压力

**新增决策(来自 02-02):**
- 从 tool_input 提取 query_params (question/query 字段) 用于日志和重放
- 基于结果结构计算 success 字段 (区分成功和错误)
- 使用 lambda 闭包将 metrics 注入 HookMatcher hooks
- 测试触发条件而非仅测试行为,验证自主工具调用机制

**新增决策(来自 02-03):**
- 验证 session_history 格式符合 Messages API 规范 (role + content)
- 测试 tool result 正确映射到 tool_result 消息类型
- 确保会话历史可用于重放和调试

**新增决策(来自 02-04):**
- 使用 empty search_results 强制 Agent 调用 NotebookLM 工具
- 三阶段诊断结构: 技能发现 → SDK 配置 → 最小工具调用
- 集成测试验证调用 AND 使用 (消除假阳性)
- 独立诊断脚本用于生产环境调试

**新增决策(来自 04-01):**
- 通过 'minimaxi.com' 模式检测 API 模式 (ANTHROPIC_BASE_URL)
- 官方 API 使用标准认证 (仅 api_key)
- MiniMax API 需要自定义 Authorization header (向后兼容)
- 官方 API 超时 120秒 vs MiniMax 推理模型 3000秒
- Temperature=0.0 在官方 API 允许,MiniMax 转换为 0.001

**新增决策(来自 04-02):**
- 使用 os.getenv('MODEL_NAME', 'claude-sonnet-4-20250514') 实现可配置默认模型
- 在 .env.example 中将 MiniMax 配置移至备用配置区域
- 创建专用迁移测试套件验证双模式行为
