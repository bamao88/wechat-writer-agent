## 一、项目概述

### 1.1 背景

作为AI产品经理训练营运营者，日常产出大量碎片化内容（群聊观点、1V1会议、课程讲解），但缺乏系统化的内容转化机制，导致高价值内容未能有效转化为公众号文章等可传播形态。

### 1.2 目标

搭建一个自动化内容生产系统，实现：

- **输入**：一个选题
- **输出**：一篇完整文章，自动写入飞书云文档，并在多维表格中创建管理记录

### 1.3 核心价值

| 指标 | 当前状态 | 目标状态 |
|------|----------|----------|
| 单篇文章生产时间 | 2-3小时 | 30分钟（含审核修改） |
| 素材利用率 | 低，大量沉淀未使用 | 高，通过检索自动关联 |
| 内容管理 | 分散，无追溯 | 集中管理，可追溯来源 |

## 二、系统架构

### 2.1 设计原则

**Agent 只做需要智能的事，确定性操作由代码处理。**

- Agent 擅长：理解选题、检索相关内容、生成文章
- 代码擅长：调用 API、上传文件、写入数据库（可靠、易调试）

### 2.2 整体流程

```
┌─────────────────────────────────────────────────────────────────┐
│                        代码编排层                                │
│                     （Python 主流程）                            │
└─────────────────────────────────────────────────────────────────┘
        │
        │  Step 1: 调用 Agent
        ▼
┌─────────────────────────────────────────────────────────────────┐
│                     内容生成 Agent                               │
│                    （Claude SDK）                                │
│                                                                 │
│   输入：选题                                                     │
│   过程：NotebookLM 检索 → 生成文章                               │
│   输出：文章标题、文章内容、素材摘要                              │
└─────────────────────────────────────────────────────────────────┘
        │
        │  Step 2: 代码调用飞书 API
        ▼
┌─────────────────────────────────────────────────────────────────┐
│                     飞书云文档写入                                │
│                    （Python 代码）                               │
│                                                                 │
│   输入：文章标题、文章内容                                        │
│   输出：云文档 URL                                               │
└─────────────────────────────────────────────────────────────────┘
        │
        │  Step 3: 代码调用飞书 API
        ▼
┌─────────────────────────────────────────────────────────────────┐
│                    飞书多维表格更新                               │
│                    （Python 代码）                               │
│                                                                 │
│   输入：选题、文章链接、时间、状态                                 │
│   输出：记录 ID                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.3 技术栈

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 编排层 | Python | 主流程控制，串联各模块 |
| 内容生成 | Claude SDK + NotebookLM Skill | Agent 处理检索和生成 |
| 飞书集成 | 飞书开放 API | 云文档创建、多维表格操作 |
| 开发方式 | Claude Code + TDD | 测试驱动开发 |

## 三、模块设计

### 3.1 模块总览

| 模块 | 职责 | 实现方式 | 可独立开发 |
|------|------|----------|------------|
| 模块A：NotebookLM 检索 | 根据选题检索相关素材 | Agent Tool (Skill) | ✅ |
| 模块B：文章生成 | 基于素材生成文章 | Agent (Claude SDK) | ⚠️ 需mock数据 |
| 模块C：飞书云文档写入 | 创建文档并写入内容 | Python 代码 | ✅ |
| 模块D：飞书多维表格更新 | 创建内容管理记录 | Python 代码 | ✅ |
| 主流程：编排层 | 串联所有模块 | Python 代码 | ❌ 依赖A-D |

---

### 3.2 模块A：NotebookLM 检索

**职责**：根据选题关键词，从 NotebookLM 知识库中检索相关素材。

**接口定义**

| 方向 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 输入 | query | string | 检索关键词 |
| 输出 | results | list | 检索结果列表 |
| 输出 | results[].content | string | 内容片段 |
| 输出 | results[].source | string | 来源标注（可选） |

**测试用例**

| 用例ID | 场景 | 输入 | 通过标准 |
|--------|------|------|----------|
| A-01 | 正常检索 | "Spec Coding方法论" | 结果非空 |
| A-02 | 结果有来源 | "Spec Coding方法论" | source 字段非空 |
| A-03 | 无结果场景 | "不存在的内容xyz" | 返回空列表，不报错 |
| A-04 | 超时处理 | 任意 | 30秒内返回或抛超时异常 |

**待确认**
- [ ] Skill 实际返回格式（需测试后更新）

### 3.3 模块B：文章生成

**职责**：基于选题和检索素材，生成符合个人风格的公众号文章。

**接口定义**

| 方向 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 输入 | topic | string | 选题名称 |
| 输入 | search_results | list | 模块A的检索结果 |
| 输出 | title | string | 文章标题 |
| 输出 | content | string | 文章正文（Markdown） |
| 输出 | source_summary | string | 使用了哪些素材的摘要 |

**Prompt 要点**

- 角色：8年经验的AI产品经理，做培训
- 风格：像跟朋友分享经验，有观点有案例，专业但不端着
- 结构：场景切入 → 分析本质 → 给出方法 → 案例说明
- 禁止：不用"首先其次最后"、不用"让我们一起来看看"

**测试用例**

| 用例ID | 场景 | 通过标准 |
|--------|------|----------|
| B-01 | 正常生成 | title 和 content 非空 |
| B-02 | 字数范围 | 1000-2500字 |
| B-03 | 格式正确 | content 以 # 开头（Markdown标题） |
| B-04 | 无模板痕迹 | 不含"[请填写]"等占位符 |
| B-05 | 无套话 | 不含"让我们一起来看看" |
| B-06 | 检索为空时 | 有明确降级策略 |

---

### 3.4 模块C：飞书云文档写入

**职责**：创建飞书云文档，写入文章内容，返回文档链接。

**接口定义**

| 方向 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 输入 | title | string | 文档标题 |
| 输入 | content | string | 文档内容（Markdown） |
| 输入 | folder_token | string | 目标文件夹 |
| 输出 | doc_url | string | 文档访问链接 |
| 输出 | doc_id | string | 文档ID |

**飞书 API 权限**

| 权限 | 用途 |
|------|------|
| docx:document:create | 创建云文档 |
| docx:document:write | 写入文档内容 |

**测试用例**

| 用例ID | 场景 | 通过标准 |
|--------|------|----------|
| C-01 | 正常创建 | 返回的 URL 包含 feishu.cn |
| C-02 | 文档存在 | 通过 API 可查询到该文档 |
| C-03 | 内容正确 | 文档内容包含输入的内容 |
| C-04 | 标题正确 | 文档标题与输入一致 |

### 3.5 模块D：飞书多维表格更新

**职责**：在多维表格中创建记录，用于内容管理。

**表格字段设计**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| 选题名称 | 文本 | 是 | 文章选题 |
| 文章链接 | 链接 | 是 | 云文档 URL |
| 创建时间 | 日期 | 是 | 自动填入 |
| 状态 | 单选 | 是 | 草稿/待审核/已发布 |
| 素材来源摘要 | 文本 | 否 | Agent 返回的摘要 |
| 目标平台 | 单选 | 否 | 公众号/小红书/视频 |
| 发布时间 | 日期 | 否 | 实际发布时间 |
| 发布链接 | 链接 | 否 | 平台文章链接 |
| 阅读量 | 数字 | 否 | 手动回填 |

**接口定义**

| 方向 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 输入 | fields | dict | 字段名到值的映射 |
| 输出 | record_id | string | 记录ID |

**测试用例**

| 用例ID | 场景 | 通过标准 |
|--------|------|----------|
| D-01 | 正常插入 | 返回 record_id 非空 |
| D-02 | 字段值正确 | 查询结果与输入一致 |
| D-03 | 必填缺失 | 抛出明确错误 |

### 3.6 主流程：编排层

**职责**：串联所有模块，实现完整流程。

**执行步骤**

```
1. 接收选题
2. 调用 Agent（检索 + 生成）→ 得到文章
3. 调用飞书 API 创建云文档 → 得到 URL
4. 调用飞书 API 插入表格记录
5. 返回结果
```

**异常处理**

| 异常场景 | 处理策略 |
|----------|----------|
| 检索失败 | 重试1次，仍失败则中止 |
| 检索无结果 | 降级：仅基于选题生成 |
| 文章生成失败 | 中止并返回错误 |
| 云文档创建失败 | 重试1次，仍失败则保存到本地 |
| 表格更新失败 | 记录日志，返回部分结果 |

**测试用例**

| 用例ID | 场景 | 通过标准 |
|--------|------|----------|
| E-01 | 端到端成功 | 表格中能查到记录，链接可访问 |
| E-02 | 检索无结果 | 仍能生成文章，有降级标记 |
| E-03 | 稳定性 | 连续10次成功率 > 90% |
